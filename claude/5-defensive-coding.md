# 방어적 코딩 게이트

`1-engineering.md`(영향 분석), `2-multi_engineering.md`(빌드 검증), `3-architecture.md`(인증·라우팅), `4-prisma-rules.md`(마이그레이션)가 *구조적* 정확성을 다룬다면, 이 파일은 *기능적* 견고성을 다룬다. 빌드를 통과해도 처리되지 않은 실패 경로는 여전히 버그다. Happy-path만 구현하는 것이 가장 흔한 실수다.

---

## 1. 코딩 전 — 실패모드 스캔

구현 전에 "이 기능이 어떻게 깨질 수 있는가"를 훑고, 이번 세션에 처리할 것과 하지 않을 것을 선언한다.

범위에 따라 깊이를 조절한다:
- **사소한 변경** (오타·단순 스타일): 한 줄로 족하다 — "빈 값·404만 처리, 동시성은 이번 범위 밖"
- **새 화면·API·결재 로직·계정 관리**: 아래 표를 전부 훑는다

| 범주 | 이 프로젝트에서 살필 것 |
|---|---|
| **입력** | null / 빈 값 / 형식 오류 / 결재 서류 첨부파일 크기·형식 / 문의 폼 스팸 |
| **네트워크·API** | 실패, 타임아웃, 401/403, 404, 409(결재 중복 승인·동시 처리), 500 |
| **상태·UI** | 로딩 / 결과 없음 / 에러 피드백 — 세 가지 상태 모두 UI 존재해야 함 |
| **동시성** | 결재 중복 클릭, 동시 승인 경합, 계정 중복 생성 |
| **권한** | 비인증 접근 / 잘못된 역할 / 어드민 경로에 일반 직원 세션 / 본인 아닌 개인정보 접근 |

## 2. "완료" 선언 전 — 기능적 완료 기준

빌드 통과 ≠ 완료. `2-multi_engineering.md`의 빌드·타입 게이트를 통과한 뒤, 아래를 추가로 충족해야 "완료"다. 미충족 항목이 있으면 완료를 선언하지 말고 남은 목록을 보고한다.

- [ ] 1단계에서 "처리하겠다"고 선언한 예외가 실제 코드에 처리됨
- [ ] 에러를 조용히 삼키지 않음 — 사용자에게 토스트 등으로 노출; `catch (e) {}` 금지
- [ ] 로딩·빈 상태에 실제 UI가 있음 (성공 상태만 만들지 않음)
- [ ] DB·프레임워크 오류를 그대로 노출하지 않고 사용자용 메시지로 번역
  - Prisma `P2002` (unique 제약 위반) → "이미 존재하는 계정입니다" 등
  - Prisma `P2025` (not found) → "존재하지 않는 항목입니다" 등
- [ ] 결재 상태 변경·계정 역할 일괄 변경 등 여러 행을 바꾸는 작업은 `prisma.$transaction()` 안에서 처리
- [ ] 내 변경으로 안 쓰게 된 import·변수·함수 제거 (기존 dead code는 언급만 하고 그대로 둠)
- [ ] 빌드·타입 통과 (`pnpm build`)
- [ ] 기능 추가·변경·삭제 시 테스트·`local/qc/`·`docs/`를 같은 세션에 동기화 (`2-multi_engineering.md` 4단계)

### 이 프로젝트 전용 추가 체크

- [ ] 권한 체크가 클라이언트에만 있고 서버에는 없는 경우 없음
- [ ] 어드민 작업(계정·콘텐츠·결재 강제 처리)에 `AuditLog` 생성됨 (`3-architecture.md` 참조)
- [ ] 결재 상태 전환이 올바른 흐름(DRAFT→IN_REVIEW→APPROVED/REJECTED→DRAFT) 내에서만 가능
- [ ] 개인정보 API 응답에 민감 필드(비밀번호·주민번호·급여 등) 미포함
