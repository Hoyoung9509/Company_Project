# 빌드 검증 루프 & 완료 기준

## 1. 일반 원칙

- **영향 분석:** 변경 전 영향받는 파일·클래스를 파악한다. 특히 `AuthInterceptor` / `AdminInterceptor` / 결재 상태 전환 메서드를 바꾸면 모든 호출부를 같은 세션에 수정한다.
- **DRY:** 세션 조회·권한 체크·결재 상태 계산 등 반복 로직은 공용 클래스로 추출한다.
- **주석:** 복잡한 로직이 *왜* 존재하는지 설명한다. 코드가 *무엇*을 하는지 반복하지 않는다.

---

## 2. 자율 빌드-디버그 루프

프로젝트의 기본 검증 게이트는 **`./gradlew build`** (컴파일 + 테스트 전체 검증)이다.
고영향 변경에는 이 루프를 반드시 실행한다. 컴파일 검증을 사용자에게 떠넘기지 않는다.

### 작업 범위 판단

- **소규모** (오타·단순 스타일·단일 변수): 루프 생략, 즉시 처리.
- **중대한 변경** (여러 파일 리팩토링·새 API·인증 로직·결재 흐름·DB 스키마 변경): 아래 5단계 루프를 강제 실행.

### 5단계 루프 (중대한 변경)

**1단계 — 구현 + 단위 테스트:**
- 변경 사항을 적용한다.
- Mapper XML을 수정했으면 `namespace`·`id`가 인터페이스와 일치하는지 확인한다.
- 순수 로직(결재 상태 계산, 권한 유틸 등)을 추가·변경했으면 `./gradlew test` 케이스를 추가하거나 실행한다.

**2단계 — 프로덕션 빌드 실행:**
```bash
./gradlew build
```
사용자에게 보고하기 전에 반드시 실행한다.

**3단계 — 자율 디버깅:**
- 빌드 실패 시 사용자에게 묻지 않는다.
- 빌드 로그·스택트레이스를 분석해 스스로 수정하고 즉시 재실행한다.
- 에러가 0이 될 때까지 반복한다.

**4단계 — QC 체크리스트 동기화 (기능 추가·변경·삭제 시):**

빌드 통과만으로 완료가 아니다. 아래를 같은 세션에 동기화한다:

| 파일 | 대상 |
|---|---|
| `local/qc/00_smoke.md` | 기본 페이지 접근, 로그인·로그아웃 |
| `local/qc/01_auth.md` | 인증·권한 흐름 (역할별 접근 차단, 세션 만료) |
| `local/qc/02_approval.md` | 결재 전체 흐름 (기안→승인→반려→재기안) |
| `local/qc/03_profile.md` | 개인정보 조회·수정, 타인 접근 차단 |
| `local/qc/04_admin.md` | 어드민 패널 (계정·콘텐츠·결재 관리, 감사 로그) |
| `local/qc/05_public.md` | 공개 페이지 (콘텐츠 정확성, 반응형) |

**5단계 — 최종 보고:**
빌드 통과 + QC 동기화 완료 후 보고. 보고 내용:
- 작업 범위 판단 근거
- 자율 수정이 있었으면 그 내용
- 업데이트한 QC 항목 (또는 필요 없는 이유)

---

## ⚠️ 절대 금지

- 빌드 실패 상태에서 "완료"로 보고하지 않는다.
- 컴파일·검증을 사용자에게 떠넘기지 않는다.
- 기능 추가·변경·삭제를 QC 동기화 없이 "완료"로 보고하지 않는다.
