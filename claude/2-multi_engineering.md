# 빌드 검증 루프 & 완료 기준

모든 코드 수정·리팩토링·기능 구현에 적용한다.

---

## 1. 일반 코딩 원칙 (모든 작업에 적용)

- **영향 분석:** 변경 전 영향받는 파일·모듈을 파악한다. 특히 `requireEmployee()` / `requireManager()` / `requireAdmin()` 같은 인증 헬퍼나 결재 상태 전환 함수를 바꾸면 모든 호출부를 같은 세션에 수정한다.
- **DRY:** 권한 체크·결재 상태 계산·개인정보 필드 필터링 등 반복 로직은 공용 함수로 추출한다.
- **간결한 주석:** 복잡한 로직이 *왜* 존재하는지 설명한다. 코드가 *무엇*을 하는지 반복하지 않는다.

---

## 2. 자율 빌드-디버그 루프

프로젝트의 기본 검증 게이트는 **`pnpm build`** (타입 오류 포함 전체 검증)이다.
고영향 변경에는 이 루프를 반드시 실행한다. 컴파일·검증을 사용자에게 떠넘기지 않는다.

### 작업 범위 판단

- **소규모** (오타·단순 스타일·단일 변수): 루프 생략, 즉시 처리.
- **중대한 변경** (여러 파일 리팩토링·새 API·인증 로직·결재 흐름·DB 스키마 변경): 아래 5단계 루프를 강제 실행한다.

### 5단계 루프 (중대한 변경)

**1단계 — 구현 + DB + 단위 테스트:**
- 변경 사항을 적용한다.
- `schema.prisma`를 수정했으면 `pnpm prisma validate`로 스키마 유효성을 확인한다. (기존 마이그레이션 SQL 파일을 직접 수정하지 않는다 — `claude/4-prisma-rules.md` 참조.)
- 결재 상태 계산, 날짜·권한 유틸 등 순수 로직을 추가·변경했으면 관련 `pnpm test` 케이스를 추가하거나 실행한다.

**2단계 — 프로덕션 빌드 실행:**
```bash
pnpm build
```
사용자에게 보고하기 전에 반드시 실행한다.

**3단계 — 자율 디버깅:**
- 빌드 실패 또는 TypeScript 오류 발생 시 사용자에게 묻지 않는다.
- 빌드 로그·스택트레이스를 분석해 스스로 수정하고 즉시 재실행한다.
- 에러가 0이 될 때까지 반복한다.

**4단계 — 테스트·QC·문서 동기화 (기능 추가·변경·삭제 시):**

빌드 통과만으로 완료가 아니다. 아래를 같은 세션에 동기화한다:

- **테스트:** 순수 로직 (`pnpm test`) 및 통합 동작(`pnpm itest`)을 추가·수정·삭제한다. 삭제된 기능의 테스트는 제거한다.
- **QC 체크리스트 (`local/qc/`):** 아래 카테고리를 현실에 맞게 유지한다. 케이스 ID는 안정적으로 유지하고 실제 코드에 근거하여 작성한다.

  | 파일 | 대상 |
  |---|---|
  | `local/qc/00_smoke.md` | 기본 페이지 접근, 로그인·로그아웃 |
  | `local/qc/01_auth.md` | 인증·권한 흐름 (역할별 접근 차단, 세션 만료) |
  | `local/qc/02_approval.md` | 결재 전체 흐름 (기안→승인→반려→재기안, 동시성) |
  | `local/qc/03_profile.md` | 개인정보 조회·수정, 타인 접근 차단 |
  | `local/qc/04_admin.md` | 어드민 패널 (계정·콘텐츠·결재 관리, 감사 로그) |
  | `local/qc/05_public.md` | 공개 페이지 (콘텐츠 정확성, SEO, 반응형) |

  변경이 상태 전환·권한·표시 동작에 영향을 주면 해당 QC 파일을 함께 업데이트한다. 검증하지 않은 케이스를 임의로 만들지 않는다.

- **문서 (`docs/`):** 사용자 대면 동작, API 표면, 설계 스펙이 바뀌면 `docs/DESIGN.md`, `docs/api/`, `docs/guide/`를 업데이트한다.

**5단계 — 최종 보고:**
빌드 통과 + 테스트·QC·문서 동기화 완료 후 보고한다. 보고 내용:
- 작업 범위 판단 근거
- 자율 수정이 있었으면 그 내용
- 업데이트한 테스트·QC·문서 (또는 필요 없는 이유)

---

## ⚠️ 절대 금지

- 빌드 실패 또는 TypeScript 오류 상태에서 중대한 변경을 "완료"로 보고하지 않는다.
- 컴파일·문법 검증을 사용자에게 떠넘기지 않는다. `bash` 도구로 직접 확인한다.
- 기능 추가·변경·삭제를 테스트·QC·문서 동기화 없이 "완료"로 보고하지 않는다.
