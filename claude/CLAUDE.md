# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## 프로젝트 개요

**회사 홈페이지** — 외부 공개 영역, 내부 직원 포털, 어드민 패널을 하나의 앱으로 제공한다.

| 사용자 유형 | 접근 경로 | 설명 |
|---|---|---|
| 외부 방문자 | `/` | 비로그인, 공개 페이지만 열람 |
| 내부 직원 | `/portal` | 세션 로그인, 결재·개인정보·공지·조직도 |
| 어드민 | `/admin` | 사이트 전체 관리 (계정·콘텐츠·결재·감사 로그) |

## 핵심 아키텍처 결정 — 변경 금지

아래는 설계 단계에서 확정한 결정이다. 구현 중 임의로 바꾸지 말고, 변경이 필요하면 먼저 이유를 밝히고 논의한다.

- **인증:** JWT 금지 — DB 기반 stateful session 사용 (상세: `claude/3-architecture.md`)
- **권한 검증:** 서버 사이드에서만 수행 — 클라이언트 권한 체크는 UI 피드백 전용
- **어드민 격리:** `/admin` 경로는 `requireAdmin()`으로 보호, 일반 직원 세션으로 접근 시 즉시 403
- **결재 상태 변경:** 반드시 DB 트랜잭션 안에서 이력(ApprovalLog)과 함께 처리
- **개인정보 API:** 응답에 불필요한 필드 포함 금지, 본인 또는 어드민만 접근

## Build & Run

> 기술 스택은 PRD 이후 확정한다. 아래는 Next.js + pnpm 기준 예정 명령어이다.

```bash
pnpm dev          # 개발 서버
pnpm build        # 프로덕션 빌드 (타입 오류 포함 전체 검증)
pnpm lint         # ESLint
pnpm test         # 단위 테스트
pnpm prisma migrate dev --name <설명>   # DB 스키마 변경 시
```

## 핵심 행동 원칙

**구현 전:**
- 가정을 명시한다. 불확실하면 묻는다. 특히 "누가 이 기능에 접근할 수 있는가"를 먼저 확인한다.
- 더 단순한 방법이 있으면 먼저 말한다. 요청하지 않은 기능, 추상화, 유연성은 만들지 않는다.

**구현 중:**
- 바뀐 모든 줄은 사용자의 요청으로 직접 추적 가능해야 한다.
- 권한 체크 함수·인증 미들웨어를 변경하면 영향받는 모든 라우트를 같은 세션에 수정한다.
- 인접 코드·포맷을 "개선"하지 않는다. 기존 스타일이 마음에 안 들어도 맞춘다.

**완료 선언 전:**
- `빌드 통과 ≠ 완료` — `claude/5-defensive-coding.md` 체크리스트를 충족해야 완료.
- 기능 추가·변경·삭제 시 테스트·QC·문서를 같은 세션에 동기화 (`claude/2-multi_engineering.md`).

## 공개 콘텐츠 작성 원칙

외부 공개 페이지(회사소개·서비스·채용·공지)를 작성하거나 편집할 때:

- **사실만 쓴다.** 제공받은 내용에 없는 회사 정보, 수치, 실적을 임의로 만들지 않는다.
- **출처를 밝힌다.** 핵심 데이터(연혁·서비스 설명·인원 등)는 어떤 자료에서 가져왔는지 명시한다.
- **정보가 없으면 멈춘다.** 빠진 내용을 업계 일반 문구로 채우지 말고 즉시 무엇이 필요한지 묻는다.

작업 중 생성된 임시 파일은 작업 완료 후 한 번에 정리한다. 작업 중간에 개별 삭제 확인으로 흐름을 끊지 않는다:
```
🧹 임시 파일 정리
1. [변환 부속 파일] 목록 → 일괄 삭제할까요? (Y/N)
2. [사용자 요청 파일] 목록 → 삭제할까요? (Y/N)
```

## 퇴근(EOD) 자동 루틴

트리거: 사용자 메시지가 `퇴근` 또는 `eod`, 또는 작업 끝에 "끝나면 퇴근 루틴 실행"이 붙은 경우.

⚠️ **중간에 확인 요청 금지.** 사용자가 자리를 비운 상태다. 판단이 애매한 것은 보류 후 요약 문서에 기록하고 다음 단계로 넘어간다.

1. **주석 패스** — 이번 세션에서 바뀐 파일만 대상으로 JSDoc 검사·추가. 런타임 코드는 건드리지 않는다.
2. **요약 문서** — `local/eod/<YYMMDD>.md`에 변경 파일·커밋 해시·작업 요약 기록. `local/`이 `.gitignore`에 없으면 추가한다. 이 문서는 커밋하지 않는다.
3. **커밋** — 이번 세션의 변경만 커밋. 세션과 무관한 기존 미커밋 작업이 섞여 있으면 귀속 불명확한 것은 커밋하지 말고 요약 문서에 상태만 남긴다. 기본 브랜치면 먼저 브랜치를 분리한다.
4. **종료** — `shutdown /s /t 60` (60초 유예, `shutdown /a`로 취소 가능). 종료 직전 작업 요약을 출력한다.

어느 단계가 실패해도 요약 문서에 성공/실패/보류 상태를 기록한 뒤 종료를 계속 진행한다.
