# Claude Code 프롬프트 가이드 — 회사 홈페이지 프로젝트

## 프롬프트 작성 원칙

**구조:** 마크다운 헤더(`## Context`, `## Instructions`)로 뼈대를 잡고, 세부 데이터 구분이 필요할 때 XML 태그(`<context>`, `<instructions>`)를 추가한다.

**순서:** 배경 정보(컨텍스트)를 먼저, 지시사항을 나중에 배치한다. 응답 품질이 높아진다.

**JSON 출력이 필요한 경우:** 결과를 `<json>` 태그로 감싸서 출력하도록 요청한다.

---

## Step 1 — PRD 작성

> Claude가 프로젝트 전체를 이해하고 방향을 잡게 한다.
> 사용자 유형이 두 가지(외부/내부)로 나뉘는 구조이므로, PRD 단계에서 이를 명확히 정의하는 것이 중요하다.

```
회사 홈페이지를 만들고 싶어. PRD를 작성해 줘.

우리 회사는 [업종/서비스]를 제공하는 [규모] 기업이야.

## 사용자 유형

외부 사용자 (비로그인):
- 회사 소개, 서비스 안내, 문의 등 공개 정보만 열람 가능

내부 직원 (로그인):
- 결재 요청 및 승인 (기안 → 중간 결재 → 최종 승인)
- 개인정보 및 프로필 관리
- 사내 공지 및 게시판
- 조직도 열람
- 권한에 따라 열람 범위가 달라짐 (일반 직원 / 팀장)

어드민 (사이트 전체 관리자):
- 홈페이지 전체를 관리하는 최상위 계정
- 내부 직원과 별도의 전용 관리 패널(/admin)에서 작업
- 일반 로그인 계정과 분리된 인증 체계 권장

## 외부 공개 섹션

- 회사 소개 (미션, 비전, 연혁)
- 서비스 / 사업 소개
- 채용 정보
- 공지사항 (외부 공개용)
- 문의 폼

## 내부 전용 기능

- 로그인 / 로그아웃 (사원번호 또는 이메일 기반)
- 결재 시스템: 문서 기안 → 결재선 지정 → 승인/반려 → 이력 조회
- 내 정보 관리: 개인정보 조회 및 수정 요청
- 사내 공지 (내부 전용)
- 조직도 (부서 / 직원 목록)

## 어드민 전용 기능

- 계정 관리: 직원 계정 생성·수정·비활성화, 역할(일반/팀장) 부여
- 콘텐츠 관리: 공개 페이지 내용 편집 (회사소개, 서비스, 채용공고, 공지사항)
- 결재 시스템 관리: 결재선 설정, 진행 중인 결재 강제 처리, 전체 결재 이력 조회
- 전체 직원 개인정보 열람
- 접속 로그 및 감사 로그 조회
- 시스템 설정 (사이트 노출 항목, 공개/비공개 전환 등)

## 기술 조건

- 기술 스택은 이 프로젝트에 적합한 것을 추천하고 이유를 설명해 줘
- 외부 / 내부 직원 / 어드민 영역을 라우팅과 인증으로 명확히 분리해야 해
- 어드민 패널(/admin)은 일반 직원 계정으로 절대 접근할 수 없어야 해
- 어드민 계정은 최소 1개, 추가 발급은 기존 어드민만 가능하도록 설계해 줘
- 결재 문서, 개인정보, 감사 로그는 보안이 중요해
- 반응형 디자인 (PC 우선, 모바일 지원)

PRD를 작성하고, 이후 단계별 구현 계획도 함께 제안해 줘.
설계 시 놓치기 쉬운 엣지 케이스(결재 반려 후 재기안, 권한 변경 시 기존 문서 처리, 어드민 계정 탈취 시 피해 최소화 방안 등)도 함께 짚어 줘.
```

## Step 2 — 단계별 구현 프롬프트로 변환

> PRD를 받은 뒤, Claude에게 직접 단계를 나누게 한다.

```
방금 작성한 PRD를 클로드 코드에서 사용할 단계별 프롬프트로 변환해 줘.
5개 내외의 핵심 단계로 나누고, 각 단계마다 명확한 목표와 완료 기준을 포함해 줘.
각 단계는 이전 단계의 결과물을 기반으로 이어지도록 구성해 줘.
```

---

## Step 3 — 각 단계 실행

> 단계별로 하나씩 실행한다. 한 번에 몰아서 요청하지 않는다.

```
Step [N]을 진행해 줘.

시작 전에 현재 프로젝트 상태를 간단히 파악하고,
어떤 순서로 작업할지 계획을 먼저 설명한 뒤 구현해 줘.
완료되면 무엇이 만들어졌는지 간략히 요약해 줘.
```

```
지금까지 완성된 부분과 남은 부분을 정리한 뒤,
[이어서 할 작업]을 진행해 줘.
```

## 개선 요청 프롬프트

> 특정 파일이나 기능을 개선할 때 사용한다.

```
@[파일명]을 분석해 줘.

<context>
[현재 상태 또는 문제 상황을 설명]
</context>

<instructions>
[원하는 개선 방향]
수정 전에 현재 코드의 문제점을 먼저 설명하고, 수정 계획을 제안한 뒤 진행해 줘.
</instructions>
```

## 상황별 자동 점검 안내

> Claude Code는 작업 맥락을 읽고 아래 상황에 해당하면 자동으로 관련 점검을 제안하거나 함께 수행한다.
> 별도 명령 없이도 다음 시점에 알아서 챙긴다.

### 새 페이지 또는 라우트를 추가할 때
- 해당 경로가 공개용인지 내부 전용인지 확인을 제안한다
- 내부 전용인데 인증 미들웨어가 없으면 즉시 경고하고 추가를 권고한다
- 역할(일반 직원 / 팀장 / 어드민) 중 어느 범위까지 접근을 허용할지 질문한다

### 인증·권한 관련 코드를 수정할 때
- 클라이언트에서만 권한을 체크하고 서버에서는 검증하지 않는 구조가 생기면 지적한다
- 권한 변경이 기존 결재 문서나 개인정보 접근에 영향을 줄 수 있으면 함께 알린다

### 결재 기능을 추가하거나 수정할 때
- 기안 → 승인 → 반려 → 재기안 흐름 중 누락된 케이스가 없는지 체크를 제안한다
- 결재선 중간 결재자가 퇴사·삭제된 경우의 예외 처리가 없으면 추가를 권고한다
- 수정 후 결재 이력이 정상 기록되는지 확인을 제안한다

### 개인정보를 다루는 API나 화면을 수정할 때
- API 응답에 불필요한 개인정보 필드가 포함되지 않는지 점검을 제안한다
- 본인 외 다른 직원의 정보가 노출될 수 있는 구조가 생기면 즉시 경고한다

### 어드민 기능을 추가하거나 수정할 때
- 어드민 전용 경로(/admin)에 일반 직원 토큰으로 접근이 차단되는지 확인을 제안한다
- 어드민이 계정을 생성·삭제·역할 변경할 때 감사 로그가 남는지 확인을 제안한다
- 어드민이 콘텐츠를 수정할 때 공개/비공개 상태가 즉시 반영되는지 확인을 제안한다
- 어드민 계정 추가 기능이 기존 어드민만 실행 가능한지 점검을 제안한다

### 배포 준비를 언급할 때
- 인증·결재·개인정보·어드민 네 영역의 점검을 순서대로 제안하고, 확인 후 배포를 진행하도록 안내한다
- placeholder 텍스트 잔존 여부와 반응형 레이아웃 확인도 함께 제안한다

## 배포 전 체크리스트

- [ ] 빌드 오류 없음
- [ ] 비로그인 상태에서 내부 전용 페이지 접근 차단 확인
- [ ] 권한별 접근 제어 동작 확인 (일반 직원 / 팀장)
- [ ] 결재 흐름 전체 동작 확인 (기안 → 승인 → 완료 / 반려 → 재기안)
- [ ] 개인정보 노출 범위 확인 (본인만 열람 가능한 항목)
- [ ] 어드민 패널(/admin) 일반 직원 토큰으로 접근 차단 확인
- [ ] 어드민 계정 추가가 기존 어드민만 가능한지 확인
- [ ] 어드민 주요 작업(계정 변경, 강제 결재 처리 등) 감사 로그 기록 확인
- [ ] placeholder 텍스트 모두 실제 콘텐츠로 교체
- [ ] 모바일 / 태블릿 / 데스크톱 시각 확인
